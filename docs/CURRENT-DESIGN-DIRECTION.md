# Current Portfolio Design Direction

> الحالة: هذا الملف هو المرجع الحالي لقرارات تصميم البورتفوليو. عند التعارض مع أفكار أقدم في `PORTFOLIO-REDESIGN-ROADMAP.md`، تكون القرارات هنا هي المعتمدة.

## القرارات الحالية

### 1. لا نعيد تصميم قسم المشاريع من الصفر

طريقة ترتيب وعرض المشاريع الحالية أعجبتنا بعد المقارنة مع مراجع أخرى، لذلك نحافظ على الـlayout الأساسي الحالي ولا نحوله إلى مشروع واحد يملأ الشاشة بالكامل ولا إلى Grid تقليدي من Cards صغيرة.

التحسين الأساسي هو أن **كل مشروع يحتفظ بهويته البصرية الخاصة حتى وهو معروض داخل الصفحة الرئيسية للبورتفوليو**.

- يبقى إطار البورتفوليو العام كما هو.
- داخل Preview كل مشروع نستخدم ألوانه، أسطحه، زواياه، وإيقاع واجهته الحقيقي.
- لا نوحد كل المشاريع على اللون الأزرق الخاص بالبورتفوليو.
- لا ننسخ الواجهة الحقيقية Pixel-for-pixel؛ نبني محاكاة صغيرة تحافظ على هوية المشروع.
- أي مشروع لا نملك مصدرًا موثوقًا لهويته لا نخترع له ألوانًا أو UI من عندنا.

### 2. الهوية الحالية للمشاريع

#### Enterprise Workflow

مصدر الهوية: مستودع المشروع الحقيقي.

- المدير: Modern dark theme، خلفيات كحلية عميقة، Primary أزرق، Borders زرقاء شفافة، Cards داكنة.
- الموظف: **Light / White theme** كامل داخل الـInteractive Demo بناءً على القرار الحالي.
- تبديل الدور يغير بيئة العمل بصريًا وليس النص فقط.

#### أكاديمية البرمجة

مصدر الهوية: `x7do0/X7do0-Academy`.

- Royal Blue.
- Light/Dark رسميان.
- أسطح أزرق/رمادي هادئة.
- Code editor يبقى LTR حتى داخل العربية.
- الـDemo يسمح بتبديل الثيم مثل المشروع الأصلي.

#### مصروفي

مصدر الهوية: `x7do0/Masroofi`.

- واجهة RTL فاتحة ونظيفة.
- أخضر للرصيد والدخل والإجراءات الإيجابية.
- الأحمر للمصروفات والحذف.
- أبيض وأس surfaces فاتحة جدًا.
- Rounded corners هادئة وظلال خفيفة.
- الـPreview داخل البورتفوليو يبقى فاتحًا لأن هذا جزء أساسي من شخصية المشروع.

#### محسوب

مصدر الهوية: `x7do0/MahsoobPOS`.

- أخضر أساسي `#126b50`.
- Sidebar أخضر داكن `#10291f`.
- خلفية فاتحة `#f4f7f5`.
- Cards بيضاء وحدود خفيفة.
- تجربة الكاشير مبنية حول Barcode + Cart + Payment في شاشة واحدة.
- لم يعد المشروع Placeholder محايدًا؛ الهوية الحالية مبنية على المصدر الحقيقي.

### 3. Interactive Demos — منفذة للأربعة

القواعد:

- كل Demo يمثل أهم Workflow فقط، وليس نسخة ثانية كاملة من التطبيق.
- البيانات معلّمة بوضوح على أنها تجريبية.
- الحالة داخل جلسة المتصفح فقط (`sessionStorage`).
- لا Login حقيقي ولا Backend/API حقيقي داخل المحاكاة.
- Reset Demo متاح.
- عربي وإنكليزي.
- كل Demo يحتفظ بهوية مشروع المصدر.

#### Enterprise Workflow

المسار:

1. موظف ينشئ طلبًا.
2. يحفظه كمسودة ويرسله.
3. يبدّل إلى المدير.
4. المدير يرى الطلب الوارد ويفتحه.
5. يوافق عليه.
6. يرجع إلى الموظف ويتأكد من الحالة الجديدة.
7. Audit Trail مصغر يسجل الإنشاء والإرسال والموافقة.

المسار: `demos/enterprise-workflow/`

قرار الثيم:
- Employee = Light / White.
- Manager = Dark.

#### محسوب

المسار:

1. اختيار منتج سريع أو إدخال Barcode تجريبي.
2. إضافة المنتج للسلة وتغيير الكمية عند الحاجة.
3. حساب الإجمالي.
4. إدخال المبلغ المستلم.
5. حساب الباقي.
6. إكمال البيع.
7. إظهار إيصال تجريبي.

المسار: `demos/mahsoob/`

#### مصروفي

المسار:

1. عرض دخل ومصروف تجريبيين ورصيد محسوب.
2. إضافة مصروف جديد.
3. تحديث الرصيد وإجمالي المصروفات والسجل فورًا.
4. حذف العملية الجديدة.
5. رجوع الأرقام إلى حالتها السابقة.

المسار: `demos/masroofi/`

#### أكاديمية البرمجة

المسار:

1. مراجعة درس Python مصغر عن المتغيرات والطباعة.
2. الانتقال إلى تمرين عملي.
3. كتابة حل داخل Editor محلي.
4. التحقق محليًا من تعريف `name` واستخدام `print(name)`.
5. عند النجاح يتحدث التقدم إلى 100%.
6. Light/Dark toggle متاح.

المسار: `demos/coding-academy/`

### 4. قسم «كيف أعمل» ملغي كمفهوم

- لا نعرض قائمة عامة تشرح "كيف أعمل".
- القسم المعتمد هو **المهارات**.
- يركز على القدرات الفعلية واللغات والتقنيات.
- طريقة العرض مستلهمة من مراجع خارجية فقط على مستوى الفكرة، بدون نسخ Layout أو Styles أو Animations حرفيًا.

### 5. اتجاه قسم المهارات

القسم مقسوم بصريًا إلى:

- Capabilities: Backend، Web Apps، Databases، Testing، Git/GitHub، AI-assisted Development.
- Languages & Technologies: C#، .NET، ASP.NET Core، EF Core، SQL Server، Python، C++، Git، GitHub وغيرها من الأدوات المثبتة فعليًا.

الهدف أن يفهم الزائر ماذا يستطيع المطور أن يبني، ثم يرى الأدوات التي يستخدمها لذلك.

### 6. Hero والصورة الشخصية — منفذ

الأصول:

- `assets/profile/profile-source.jpg` — المصدر الأصلي ولا يتم تعديله.
- `assets/profile/profile-cutout.png` — النسخة الشفافة التي جهزها المستخدم واعتمدها للعرض.

الاتجاه الحالي:

- الصورة الشخصية في أول الموقع داخل الـHero.
- الشخص جزء من Composition وليس داخل Card منفصل.
- الصورة هي العنصر البصري الرئيسي مقابل النص.
- الـSystem Window القديم تحول إلى طبقة تقنية خافتة خلف الصورة.
- يوجد Editorial typography خافت باسم `X7DO0`.
- ضبط مستقل لـDesktop / Tablet / Mobile.

ملف الدمج: `hero-profile.css`

### 7. Browser QA — جزء ثابت من سير العمل

تم اعتماد نفس الفلسفة التي نجحت أثناء تطوير مصروفي:

- خادم Static محلي داخل CI.
- Chromium حقيقي عبر Playwright.
- فحص Console errors وPage errors.
- Desktop + Mobile screenshots.
- فحص العربية والإنكليزية.
- فحص روابط صفحات المشاريع والـDemos.
- E2E فعلي لكل Demo.

الاختبارات موجودة في:
- `tests/portfolio.spec.js`

والـWorkflow:
- `.github/workflows/portfolio-qa.yml`

لا نعتمد تغييرًا بصريًا مهمًا لمجرد أن CSS صحيح؛ نراجع Screenshot ناتجًا من المتصفح الحقيقي.

## ما تم تنفيذه حتى الآن

- الحفاظ على layout المشاريع الحالي.
- إعطاء المشاريع الأربعة هويات مصدرية منفصلة داخل الصفحة الرئيسية.
- تحويل محسوب ومصروفي من Placeholders إلى مشاريع كاملة داخل المحتوى الثنائي اللغة.
- صفحات Detail للمشاريع الأربعة.
- زر `جرّب المشروع / Try the project` لكل مشروع.
- Interactive Demo لكل مشروع.
- Enterprise Employee Light / Manager Dark.
- قسم المهارات الجديد بدل «كيف أعمل».
- الصورة الشخصية الشفافة داخل Hero.
- Browser QA وE2E وسكرينشوتات مرجعية آلية.

## الخطوات التالية

1. مراجعة الصور النهائية لكل Demo بعد كل تعديل بصري مهم.
2. إضافة Media حقيقية ودراسات حالة عندما يتم اعتماد محتواها.
3. ضبط أي تفاصيل دقيقة في Hero/Skills/Project previews بناءً على المعاينة الفعلية، بدون إعادة بناء الشكل من الصفر.
4. عدم توسيع الـDemos إلى تطبيقات كاملة؛ تبقى Product Showcases سريعة ومركزة.
