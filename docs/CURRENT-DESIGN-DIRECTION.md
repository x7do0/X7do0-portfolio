# Current Portfolio Design Direction

> الحالة: هذا الملف هو المرجع الحالي لقرارات تصميم البورتفوليو. عند التعارض مع أفكار أقدم في `PORTFOLIO-REDESIGN-ROADMAP.md`، تكون القرارات هنا هي المعتمدة.

## القرارات الحالية

### 1. لا نعيد تصميم قسم المشاريع من الصفر

طريقة ترتيب وعرض المشاريع الحالية أعجبتنا بعد المقارنة مع مراجع أخرى، لذلك نحافظ على الـlayout الأساسي الحالي ولا نحوله إلى مشروع واحد يملأ الشاشة بالكامل ولا إلى Grid تقليدي من Cards صغيرة.

التحسين الأساسي هو أن **كل مشروع يجب أن يحتفظ بهويته البصرية الخاصة حتى وهو معروض داخل الصفحة الرئيسية للبورتفوليو**.

هذا يعني:

- يبقى إطار البورتفوليو العام كما هو.
- داخل Preview كل مشروع نستخدم ألوانه، أسطحه، زواياه، وإيقاع واجهته الحقيقي.
- لا نوحد كل المشاريع على اللون الأزرق الخاص بالبورتفوليو.
- لا ننسخ الواجهة الحقيقية Pixel-for-pixel؛ نبني محاكاة صغيرة تحافظ على هوية المشروع.
- أي مشروع لا نملك مصدرًا موثوقًا لهويته لا نخترع له ألوانًا أو UI من عندنا.

### 2. الهوية الحالية للمشاريع

#### Enterprise Workflow

مصدر الهوية: مستودع المشروع الحقيقي.

- Modern dark theme.
- خلفيات كحلية عميقة.
- Primary أزرق.
- Borders زرقاء شفافة.
- Cards داكنة مع glow خفيف.

#### أكاديمية البرمجة

مصدر الهوية: مستودع `X7do0-Academy`.

- Royal blue accent.
- أسطح أزرق/رمادي هادئة.
- تصميم تعليمي واضح.
- دعم Light/Dark، ويمكن للـPreview استخدام النسخة الداكنة لتنسجم داخل البورتفوليو مع الحفاظ على هوية الأكاديمية.

#### مصروفي

مصدر الهوية: مستودع `Masroofi`.

- واجهة RTL فاتحة ونظيفة.
- أخضر هو اللون الأساسي.
- أبيض وأس surfaces فاتحة جدًا.
- الأحمر للمصروفات والحذف.
- Rounded corners هادئة وظلال خفيفة.
- الـPreview داخل البورتفوليو يجب أن يبقى فاتحًا حتى لو كان البورتفوليو نفسه داكنًا، لأن هذا جزء من شخصية المشروع.

#### محسوب

- الاسم والنوع معروفان فقط حاليًا: مشروع كاشير.
- لا يوجد مصدر موثوق متاح حاليًا لهويته البصرية داخل GitHub باسم واضح.
- يمنع اختراع ألوان أو شكل نهائي له.
- يبقى Preview مؤقت ومحايد حتى يتم ربط مستودعه أو توفير Screenshots/Design source.

### 3. Interactive Demos

الفكرة السابقة ما زالت معتمدة:

- كل مشروع يحصل لاحقًا على Demo مصغر تفاعلي.
- الـDemo يحاكي أهم 1–3 workflows فقط.
- المشاريع متعددة الأدوار تحصل على Role Switcher.
- مثال Enterprise Workflow: موظف ينشئ طلب → يرسل → تبديل إلى مدير → المدير يراجع ويوافق → العودة للموظف لرؤية الحالة.
- Reset Demo متاح.
- بيانات واضحة أنها تجريبية.
- لا Backend حقيقي مطلوب للنسخة الأولى من المحاكاة.

### 4. قسم «كيف أعمل» ملغي كمفهوم

القسم السابق لا يضيف قيمة كافية ويقطع تسلسل الصفحة.

القرار:

- لا نعرض قائمة عامة تشرح "كيف أعمل".
- نستبدله بقسم **المهارات**.
- يركز على القدرات الفعلية واللغات والتقنيات.
- نعرض المهارات بصريًا بطريقة أقوى من قائمة Badges تقليدية.
- نستلهم من مراجع خارجية طريقة إعطاء اللغات والمهارات مساحة وحركة، لكن بدون نسخ Layout أو Styles أو Animations حرفيًا.

### 5. اتجاه قسم المهارات

القسم ينقسم بصريًا إلى جزأين:

- Capabilities كبيرة وواضحة: Backend، Web Apps، Databases، Testing، Git/GitHub، AI-assisted Development.
- Languages & Technologies: C#، .NET، ASP.NET Core، EF Core، SQL Server، Python، C++، Git، GitHub وغيرها من الأدوات المثبتة فعليًا.

الهدف أن يفهم الزائر ماذا يستطيع المطور أن يبني، ثم يرى الأدوات التي يستخدمها لذلك.

لاحقًا يمكن ربط Skill بالمشاريع التي تثبت استخدامها بدل عرض المهارة كادعاء منفصل.

### 6. Hero والصورة الشخصية

ما زال القرار معتمدًا:

- إضافة صورة شخصية قوية في أول الموقع.
- الصورة تكون احترافية وعالية الدقة ومصممة لتنسجم مع الواجهة.
- لا يتم توليد النسخة النهائية بدون صورة مرجعية حقيقية.
- بعد توفير الصورة نحدد Crop للديسكتوب والموبايل ونصدر WebP/AVIF مناسبة للموقع.

## ما بدأ تنفيذه

- الحفاظ على layout المشاريع الحالي.
- إضافة طبقة Styling مستقلة لهويات المشاريع بدون إعادة بناء CSS القديم.
- تطبيق هوية مصدرية لـ Enterprise Workflow.
- تطبيق هوية مصدرية لأكاديمية البرمجة.
- تطبيق هوية مصدرية لمصروفي.
- إبقاء محسوب محايدًا بدل اختراع تصميم له.
- تحويل «كيف أعمل» إلى قسم مهارات فعلي.
- إعادة تصميم عرض المهارات واللغات/التقنيات بصريًا.

## الخطوات التالية

1. مراجعة النسخة بصريًا على Desktop وMobile.
2. ضبط تفاصيل Section المهارات بعد المعاينة الفعلية.
3. ربط مصدر محسوب الحقيقي واعتماد هويته.
4. إضافة الصورة الشخصية إلى Hero بعد توفير المرجع.
5. بناء أول Interactive Demo؛ الأولوية المقترحة Enterprise Workflow لأنه أوضح مشروع لإظهار Role Switching.
